## Purpose

Every change to the offering is recorded, reviewed, tested and reversible.

## Scope

All Orrinwick staff and contractors, and every information resource marked in scope in mas/mas-record.json.

This policy covers these information resources from the scope record:

| ID | Resource |
|---|---|
| E1 | Source control (hosted) |
| E2 | CI/CD pipeline |
| E3 | Infrastructure as code state and runners |
| P1 | Production cloud accounts and network |
| P2 | Application compute (API, routing engine, notification workers, web console) |
| P11 | Container registry and artifact store |

## Requirements

| ID | Requirement | KSIs |
|---|---|---|
| CMT-1 | Every change to a production resource is made through the pipeline. The pipeline logs the change, the author, the reviewer and the result. | KSI-CMT-LMC |
| CMT-2 | Production machine-based resources are replaced from a trusted image or build. Staff do not modify running resources by hand. | KSI-CMT-RMV |
| CMT-3 | The Platform Lead reviews the change procedure each year and after any failed or emergency change. | KSI-CMT-RVP |
| CMT-4 | Every deployment runs automated tests for integrity and security before release and checks that the deployed state matches the intended state after release. | KSI-CMT-VTD |
| CMT-5 | A change that matches a significant change rule is entered in the significant change log. The GRC Lead sends the required notice within the rule timeline (SCN rules). | KSI-CMT-LMC, KSI-CMT-RVP |

Status is a simulated validator result. Class C needs at least two automated methods per KSI (`FRC-CSX-VVK`).

## Exceptions

An exception needs a written request, a named risk owner, a compensating control and an expiry date of no more than 90 days. The GRC Lead records approved exceptions in docs/security-decision-record.md. An expired exception is a policy violation.

## Enforcement

Violations are reported to the GRC Lead. Staff violations follow the personnel security process (N5).
