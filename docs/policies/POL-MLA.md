## Purpose

Security-relevant events are recorded, protected, searched and reviewed.

## Scope

All Orrinwick staff and contractors, and every information resource marked in scope in mas/mas-record.json.

This policy covers these information resources from the scope record:

| ID | Resource |
|---|---|
| E4 | Production logging, monitoring and alerting stack |
| P1 | Production cloud accounts and network |
| P2 | Application compute (API, routing engine, notification workers, web console) |
| P3 | Managed relational database |
| P4 | Object storage |
| P8 | Load balancer, API gateway and web application firewall |
| E6 | Privileged access management and production access gateway |
| E7 | Workforce identity provider (SSO and MFA) |

## Requirements

| ID | Requirement | KSIs |
|---|---|---|
| MLA-1 | Log access is limited to named security and operations roles. Log changes and deletions raise an alert. | KSI-MLA-ALA |
| MLA-2 | Resource configurations are evaluated against the baseline at least daily. | KSI-MLA-EVC |
| MLA-3 | Each in-scope resource logs authentication, authorisation, administrative, configuration and data-access events. Logs do not contain alert summaries or credentials. | KSI-MLA-LET |
| MLA-4 | Logs flow to the security monitoring stack (E4), which correlates events and raises alerts. | KSI-MLA-OSM |
| MLA-5 | Security staff review alerts daily and review log coverage each quarter. Logs are kept for 12 months. | KSI-MLA-RVL |

## Exceptions

An exception needs a written request, a named risk owner, a compensating control and an expiry date of no more than 90 days. The GRC Lead records approved exceptions in docs/security-decision-record.md. An expired exception is a policy violation.

## Enforcement

Violations are reported to the GRC Lead. Staff violations follow the personnel security process (N5).
