## Purpose

Configuration, secrets, communications and data in the offering are managed by automation and checked against the intended state.

## Scope

All Orrinwick staff and contractors, and every information resource marked in scope in mas/mas-record.json.

This policy covers these information resources from the scope record:

| ID | Resource |
|---|---|
| P1 | Production cloud accounts and network |
| P2 | Application compute (API, routing engine, notification workers, web console) |
| P3 | Managed relational database |
| P4 | Object storage |
| P5 | Key management service |
| P6 | Secrets management service |
| P7 | Message queue and job scheduler |
| P8 | Load balancer, API gateway and web application firewall |
| P9 | DNS and certificate management |
| E2 | CI/CD pipeline |
| E3 | Infrastructure as code state and runners |

## Requirements

| ID | Requirement | KSIs |
|---|---|---|
| SVC-1 | Resource configuration is applied by automation. Manual configuration is a defect. | KSI-SVC-ACM |
| SVC-2 | Secrets live in secrets management (P6). Keys are held in the key management service (P5). Secrets rotate at least every 90 days and never appear in code, logs or tickets. | KSI-SVC-ASM |
| SVC-3 | The security team evaluates new tools and findings every quarter and records the improvements made. | KSI-SVC-EIS |
| SVC-4 | The offering does not keep residual access, credentials or data after a change. Deprecated resources are removed within 30 days. | KSI-SVC-PRR |
| SVC-5 | Customer data is deleted from production within 30 days of a verified customer request and from backups at the next backup expiry. Staging holds synthetic data only. | KSI-SVC-RUD |
| SVC-6 | Data at rest is encrypted. Queues, tables and volumes use customer-data keys from the key management service. | KSI-SVC-SIN |
| SVC-7 | Every data flow in the scope record uses TLS 1.2 or later with a valid certificate. Certificates renew automatically. | KSI-SVC-VCM |
| SVC-8 | Deployed images and packages are signed. The pipeline verifies the signature and a digest before release. | KSI-SVC-VRI |

## Exceptions

An exception needs a written request, a named risk owner, a compensating control and an expiry date of no more than 90 days. The GRC Lead records approved exceptions in docs/security-decision-record.md. An expired exception is a policy violation.

## Enforcement

Violations are reported to the GRC Lead. Staff violations follow the personnel security process (N5).
